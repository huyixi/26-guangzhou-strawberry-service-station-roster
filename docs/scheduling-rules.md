# 音乐节公平排班算法 v3

## 1. 硬约束

1. 排班日期为演出日（`09-25`、`09-26`、`09-27`），值班窗口为每天 `12:00–21:30`；所有成员这三天均可参与排班。
2. 每天 `12:00–21:30` 任意时刻至少 4 人在岗。
3. 任意个人单次连续值班不得超过 150 分钟。
5. 换班时使用 3 分钟重叠，避免交接出现空档。
6. 每段连续在岗时间至少 40 分钟；同一天相邻两段班次之间的离岗休息至少 40 分钟。首班前和末班后的离岗时间不计入此规则。

v3/v4 版本要求任意时刻至少 1 名男性在岗；v5/v6 不设置男性覆盖要求，允许出现全女性在岗时段。各版本每天仍至少 4 人在岗。

当前排班器按每天恰好 4 人在岗求解，不主动安排额外重叠；这满足最多约 3 分钟的重叠上限。

## 2. 排班优化目标

按以下优先级优化：

1. 在三天总工时差不超过 180 分钟的范围内，优先满足“必须看”。填写“必须看”较少的人优先；按填写场数从少到多逐组优化，同组内尽量增加满足数。
2. 再依次增加“特别想看”和“有点想看”的满足数，所有填写的艺人都计入，不受偏好计分名额限制。
3. 在上述目标确定后，尽量缩小三天总工时差。
4. 单次值班原则上不少于 60 分钟，并尽量接近 75 分钟；40–59 分钟的班次允许出现，但优化时优先避免。
5. 尽可能至少 1 名男性在岗。
5. 收尾班尽量平均分配。
6. 尽量减少不必要的换班。

“必须看”目前仍是最高优先级的软需求。若有人确认某场绝对不能错过，应先核对该要求与岗位覆盖是否相容，再作为硬约束加入。

## 3. 偏好计分

| 偏好 | 分数 | 
| --- | ---: |
| 必须看 | 100 |
| 特别想看 | 30 |
| 有点想看 | 10 |

## 4. 指标口径

主要指标为全部需求满足率和“必须看”满足率：满足数除以填写数。只有完整观看某艺人的至少一场演出，该项需求才算满足。未满足清单列出全部填写的需求。

原有百分比改称“限额偏好得分率”，只用于兼容原计分规则，不代表全部需求满足率：

```text
限额偏好得分率 = 实际获得的偏好分 ÷ 个人全部计分名额对应的总分
```

例如某人有：

* 3 个“必须看”计分名额
* 4 个“特别想看”计分名额
* 1 个“有点想看”计分名额

则满分为：

```text
3×100 + 4×30 + 1×10 = 430
```

如果实际获得 300 分：

```text
限额偏好得分率 = 300 ÷ 430 ≈ 69.8%
```

## 5. 什么算“看到了”

一条艺人需求视为满足，条件是本人在该艺人的至少一场演出期间，以及演出前后各 5 分钟，都没有值班。

同一时间有多场演出时，每场分别判断。如果本人在这些演出期间都没有值班，则这些演出对应的多条需求都计为满足；不要求本人只能选择其中一场。

要求：

```text
值班结束时间 ≤ 演出开始时间 - 5分钟
下一次值班开始时间 ≥ 演出结束时间 + 5分钟
```

与本人班次冲突的场次不计入可观演；同一艺人有多场时，只要至少一场不冲突，该艺人需求就算满足。

## 核心原则

> 先保证岗位覆盖和工时差上限，再优先满足填写较少的“必须看”需求，随后处理其他需求并平衡工时。
